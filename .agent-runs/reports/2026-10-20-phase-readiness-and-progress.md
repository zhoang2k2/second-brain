## Non-interactive execution boundary

Once BOSS supplies the phase answers and a bounded authorization, the agent should not ask for routine implementation approvals. It may make technical choices inside that scope, use synthetic data, run approved local checks, fix related defects, and commit locally on the selected feature branch.

No-question execution does not grant access or authority that has not been provisioned. Current Phase 1 authorization still excludes cloud, additional model downloads, secret-bearing files, unrelated repos/vaults, purchases/hosting, external messages, push, deployment, and protected-branch merges. A phase 3 agent can avoid per-action prompts only for a pre-approved batch whose exact target, action types, limits, expiry, and revocation path have been configured. A missing owner-only setup or decision blocks only dependent work; the agent must continue independent work and report the precise gate. It must not invent facts/permissions or label an external acceptance step done.

"100% done" is an objective, not a result that can be guaranteed before hardware, providers, clients, permissions, and owner acceptance are exercised. Report each phase as `ready`, `in progress`, `waiting for owner setup/acceptance`, or `blocked by technical finding` with evidence.
